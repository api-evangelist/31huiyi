# 31huiyi (31会议 / 31Event)

> Digital event and exhibition SaaS platform operated by Shanghai Bayantu Information Technology Co.,
> Ltd. (上海八彦图信息科技有限公司), Shanghai, China, founded 2010. Products cover conference management
> (31大会易), lightweight event management (31轻会), exhibition management (31展览云), on-site smart
> check-in and reception (31智慧现场), virtual events and an event AI assistant (31智伴).

## API at a glance

- Name: 31 OpenAPI
- Base URL (production): https://31api.31huiyi.com
- Base URL (test): https://test2-31api.31huiyi.com
- Authorization server: https://oauth.31huiyi.com (OAuth 2.0 / OpenID Connect, IdentityServer)
- Developer center: https://api-help.31huiyi.com/zh/home
- Machine-readable contract: NONE PUBLISHED. No OpenAPI, Swagger, GraphQL SDL, AsyncAPI, Protobuf or
  WSDL document exists. 86 operations are documented as HTML tables across 93 developer-center pages.
- Style: RPC-over-HTTP. 85 of 86 documented operations are POST to a verb-named path under /op/,
  including reads. HTTP method does not signal safety.
- Response envelope: HTTP 200 with {businessCode, businessMessage, data} (or
  {sysCode, sysMessage, isSuccess, returnObj, pager} on the account family). Not RFC 9457.

## Getting started

- Credentials are NOT self-service. 31's integration staff issue an appKey (client id) and appSecret.
  https://api-help.31huiyi.com/zh/home
- Token: POST https://oauth.31huiyi.com/connect/token, application/x-www-form-urlencoded,
  grant_type=custom_user_code, client_id=openapi, method=client_secret,
  scope="offline_access OpenAppGateway", appKey, appSecret.
- Access token TTL 30 minutes; refresh token TTL 2 hours. Send as `Authorization: Bearer <token>`.
- OIDC discovery: https://oauth.31huiyi.com/.well-known/openid-configuration (served, HTTP 200)
- Postman collection: https://api-help.31huiyi.com/openapi.postman_collection.json (v2.1.0, 4 requests)
- Partner SSO handshake: https://api-help.31huiyi.com/zh/oauth

## Data sensitivity

The attendee surface carries direct personal data (name, mobile, email, ID number, photo), national ID
verification and face recognition, under PRC PIPL. No consent, export or data-subject-request operation
is documented on the API.
